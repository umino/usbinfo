usbinfo / Windows デバイス調査ツール

usbinfo のしくみ

接続中のディスクのうち「USB で外付けされた、取り外せるストレージ」はどれかを判定するために、Windows から取れる値をまとめてダンプするツールです。プログラムは読めるけれど USB の仕様には詳しくない人向けに、動きを図で説明します。

1何を調べるツールか

Windows にはディスクの情報を返す API がたくさんあり、それぞれが「取り外せる」「USB だ」といった値を返します。ところが、どの値が正しく当たるかは機器によって違います。たとえば「リムーバブル」を返す API は、USB の SSD に対して「固定ディスク」と答えます。

そこで usbinfo は、取れる値をすべて並べて出力し、実機で比べられるようにしています。1 ファイルの C++ コンソールアプリ（usbinfo.cpp）で、管理者権限はいりません。

結論を先に言うと、判定には「ディスクであること」「デバイスの木をたどると USB に行き着くこと」「OS が取り外しを想定していること」の 3 つを組み合わせます。以下はその理由と、値の取り方の説明です。

2Windows はデバイスを「木」で管理している

Windows は、つながっている機器を親子関係のある木構造で管理しています。木の各ノードを devnode と呼びます。プログラムからは CM_Get_Parent() で親をたどれて、各ノードは DEVPKEY_* というキーでプロパティを持っています。デバイスマネージャーの「表示 → デバイス (接続別)」で見えるのがこの木です。

下の図は、今回の調査で使った 3 種類のディスクの木です。いちばん下のディスクから上へ親をたどります。

USB ストレージには 2 つの転送方式がある

USB ストレージは、中身は SCSI コマンドで、それを USB でどう運ぶかに 2 種類あります。方式によって Windows が使うドライバーが変わり、ディスクの ID の形まで変わります。

BOT · Bulk-Only Transport

昔からある方式です。ドライバーは USBSTOR で、ディスクの ID は USBSTOR\Disk&… になります。ID を見れば USB と分かります。

UAS · USB Attached SCSI

新しく速い方式です。ドライバーは UASPStor で、ディスクの ID は SCSI\Disk&… になります。内蔵 NVMe と同じ形なので、ID だけでは USB と分かりません。

このため usbinfo は ID の文字列を見ず、親をたどって「親が USB ハブであるノード」があるかで USB 経由かどうかを決めます。ハブの直下にいるノードが USB デバイス本体です。この方法なら BOT、UAS、ハブ経由のどれでも同じように判定できます。

3USB の情報は「親のハブ」に聞く

USB 機器は自分の自己紹介データ（ディスクリプタ）を持っています。ベンダー ID、製品 ID、シリアル番号、機器の種類などが入った構造体です。ただし、アプリが機器から直接読むことはできません。機器がつながっている親のハブに、ポート番号を指定して問い合わせます。

  1. 1

    親のハブを見つける

    USB 機器の devnode から親をたどり、ハブのデバイスインターフェイス（CreateFile できるパス）を得ます。

    CM_Get_Parent / GUID_DEVINTERFACE_USB_HUB
  2. 2

    何番ポートに挿さっているかを調べる

    USB 機器の devnode のプロパティに、親ハブ上のポート番号が入っています。

    DEVPKEY_Device_Address
  3. 3

    ハブを開いてポート番号付きで問い合わせる

    VID/PID、接続速度、デバイスアドレス、外部端子か Type-C か、製品名やシリアル番号の文字列が取れます。

    IOCTL_USB_GET_NODE_CONNECTION_INFORMATION_EX
    IOCTL_USB_GET_PORT_CONNECTOR_PROPERTIES
    IOCTL_USB_GET_DESCRIPTOR_FROM_NODE_CONNECTION

4処理の流れ

wmain の中身は次の 5 段階です。判定は 3 段目で行います。

  1. 1

    USB 機器を全部集める

    USB 機器を全部列挙し、前節の方法で各機器の情報を取ります。結果はキャッシュしておき、3 段目でディスクと結び付けるときに使います。

    GUID_DEVINTERFACE_USB_DEVICE → usbInfo()
  2. 2

    周辺の情報を集める

    ボリューム（ドライブレター、ファイルシステム）、WMI（Get-Disk と同じ情報）、WPD（エクスプローラーの「ポータブル デバイス」）を集めます。

    FindFirstVolume / Win32_DiskDrive ほか / WPD クラスの devnode
  3. 3

    ディスクを 1 台ずつ調べて判定する

    ディスク、光学ドライブ、フロッピーを列挙します。各ドライブについて、ストレージ IOCTL でバス種別や容量を取り、devnode の親をたどって USB デバイス本体を探し、判定します。ドライブはアクセス権 0 で開くので、中身を読めない壊れたディスクでも判定できます。

    processDisk() / IOCTL_STORAGE_QUERY_PROPERTY ほか
  4. 4

    ボリュームからも対応付ける

    ボリュームを起点にした場合に、どのディスクのどの判定結果になるかを一覧にします。

    GUID_DEVINTERFACE_VOLUME → IOCTL_STORAGE_GET_DEVICE_NUMBER
  5. 5

    出力する

    text / json は全情報、csv はディスク 1 台 1 行の比較表だけを出します。lsusb / lsusb-tree を選んだときは 1〜4 を飛ばし、USB の接続ツリーだけを表示します。

5判定のフロー

各ドライブの verdict は次の順番で決まります（processDisk() の判定部分と同じ順序です）。A・J・C の 3 つをすべて通ったものだけが判定対象のストレージになります。

6なぜ 1 つの値では判定できないのか

よく使われる値を 1 つだけ使って判定した場合に、実機で当たったか（○）外れたか（×）を並べました。どの値にも外れる機器があります。3 つの条件を組み合わせた右端の列だけが全部当たります。

機器 期待 BusType が Usb GetDriveType が REMOVABLE RemovableMedia ビット WPD に出る 取り外しポリシー A∧J∧C
内蔵 NVMe SSD対象外 NvmeFIXEDfalseなしNoRemovalNOT_USB
ポータブル SSD（UAS、APFS）対象 UsbレターなしfalseなしSurpriseREMOVABLE
USB-SATA 変換（BOT、NTFS）対象 UsbFIXEDfalseありSurpriseREMOVABLE
NVMe ケース（UAS、読めない）対象 UsbレターなしfalseなしSurpriseREMOVABLE
外付け BD ドライブ対象外 UsbCDROMtrueなしSurpriseOPTICAL

GetDriveType と RemovableMedia

名前に反して「メディアが抜けるか」（カードやディスクを入れ替えられるか）という意味です。USB の SSD は機器ごと抜くものなので「固定」と答え、BD ドライブは「抜ける」と答えます。判定したいことと逆になります。

WPD（ポータブル デバイス）

Windows が読めるファイルシステムをマウントしたときにだけ現れます。Mac 用にフォーマットしたディスクや、未フォーマットのディスクは出ません。

BusType と取り外しポリシー

どちらも USB の SSD には正しく当たりますが、BD ドライブも「USB で取り外せる」と答えます。光学ドライブを外すには、ディスクとして列挙されたかどうか（J）を組み合わせる必要があります。

読めないディスクでも判定できる

A・J・C はどれも devnode と列挙の情報で、ディスクの中身を読みません。容量すら取れない NVMe ケースでも正しく判定できました。

7内蔵か外付けかを見分ける補助情報

USB でつながっていても PC に内蔵されている機器があります（Bluetooth アダプター、内蔵カメラ、ノート PC の内蔵カードリーダーなど）。USB デバイス本体については、次の 3 つの値が参考になります。今回の実機では、外付け機器と内蔵機器がきれいに分かれました。

値意味外付け機器内蔵機器
capRemovable機器が親から取り外せる扱いかtruefalse
inLocalMachineContainerPC 本体と同じ「物理的な箱」に属するかfalsetrue
portUserConnectable挿さっているのが外に出ている端子かtruefalse

これらは PC のファームウェア（ACPI）の記述をもとにしているので、記述が不正確な機種では内蔵機器が外付けと報告されることがあります。

8ボリュームからたどるときの落とし穴

ドライブレターなどのボリュームから判定したい場合は、ボリュームに IOCTL_STORAGE_GET_DEVICE_NUMBER を送ってディスク番号を得て、そのディスクの判定結果を使います。ボリュームの devnode の親をたどってもボリュームマネージャーに行き着くだけで、USB には届かないためです。

STORAGE\Volume\…→ IOCTL →Disk, 1→\\.\PhysicalDrive1 通常のボリュームは、種類と番号でディスクと正しく対応付けられます。
フロッピーのボリューム→ IOCTL →Disk, 0→\\.\PhysicalDrive0 ? フロッピーも種類が「ディスク」で返り、番号はフロッピーの通し番号です。番号で探すと、無関係な PhysicalDrive0 に結び付いてしまいます。フロッピーはボリュームの devnode 自身から親をたどります。

9用語

devnode
デバイスの木の 1 ノード。CM_Get_Parent で親をたどれる。
インスタンス ID
devnode の ID 文字列。先頭はそのノードを作ったバスドライバー（USB\、USBSTOR\、SCSI\ など）。
デバイスインターフェイス
「ディスク」「USB 機器」などの種類ごとの GUID。これで列挙すると、その種類の機器を CreateFile で開けるパスが得られる。
IOCTL
DeviceIoControl() でドライバーに送る問い合わせコマンド。
ハブ / ポート
ハブは USB の分岐点で、PC 本体の端子もルートハブという 1 つのハブ。ポートはハブの差し込み口で、1 から番号が付く。
ディスクリプタ
USB 機器が持つ自己紹介の構造体。VID/PID、シリアル番号、機器の種類などが入っている。
VID / PID
ベンダー ID と製品 ID（各 16 ビット）。152d:2329 のように書き、メーカーと機種を表す。
BOT / UAS
USB ストレージの転送方式。BOT は USBSTOR、UAS は UASPStor ドライバーで動く。
取り外しポリシー
OS がその機器の取り外しをどう想定しているか。ExpectNoRemoval（外さない）、ExpectOrderlyRemoval、ExpectSurpriseRemoval（いつ抜かれてもよい）の 3 つ。

10まだ確かめていないこと

調査は Windows 11 のデスクトップ PC 1 台で行いました。次の条件は試していないので、判定方法を採用する前に実機で verdict を確認してください。

  • Windows 10 での動作
  • USB メモリ、カードリーダー（メディアあり・なし、複数スロット）
  • ノート PC の内蔵カードリーダーなど、内蔵の USB 接続ストレージ
  • eSATA や SD ホストコントローラーなど、USB 以外の取り外し可能ストレージ
  • ベンダー製ドライバーを使う USB ストレージ
  • メディアを入れた光学ドライブ、スマートフォンなどの MTP 機器
  • ほかの機種の PC（ACPI の記述の違い）
