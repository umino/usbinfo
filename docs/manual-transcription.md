# 検証結果を目コピで持ち帰る手順

既存コードのある環境では、ファイルのコピーができず、検証結果も目で見て写すしかありません。
`usbinfo -f code` は、判定に必要な情報だけを 1 ドライブ 1 行の短いコードにして出力します。写したコードを手元の PC で `--decode` にかけると、写し間違いを検出して元の内容に展開できます。

## 手順

1. 検証環境で実行し、画面に出たコードを紙やメモに写します。

   ```
   usbinfo -f code
   ```

   `usbinfo --all` でも、最後に同じ内容 (`--vidpid` 付き) が表示されます。ファイルへの保存とあわせて行いたいときはこちらを使います。

   ```
   UI3 N03 8F
   C: FNN U GS NN N-- NN UN 99
   D: RYY S UU YN SYN YU SY 5D
   E: FNY S GU NN SYN YU SY 0F
   ```

   (上は例です。実際に画面に出た値を写してください。)

2. 手元の PC で、写したコードをテキストファイルに打ち込み、検証します。

   ```
   usbinfo --decode typed.txt
   ```

3. `NG` の行があれば、その行だけ検証環境の画面と見比べて直します。
4. `RESULT: OK` になったら、コードか展開結果を Claude に貼り付けます。

空白、`:`、大文字小文字の違いは無視するので、`efnysgunnsynyusy0f` のように続けて打っても検証できます。`#` で始まる行はメモとして無視します。機器の状態などを `# E: USB-SATA の SSD` のように書き添えられます。

## 検出できる写し間違い

- **1 文字の間違い**: 各行末の CRC-8 で必ず検出します。
- **行の抜け**: ヘッダーの行数 (`N03`) と比べて検出します。
- **2 文字以上の間違いや入れ替え**: ほぼ検出しますが、約 1/256 の確率ですり抜けます。

## コードの読み方

```
E: FNY S GU NN SYN YU SY 0F
```

| 位置 | 例 | 意味 | 値 |
|---|---|---|---|
| 1 | `E:` | ドライブレター | |
| 2 | `F` | `GetDriveType` | `R` REMOVABLE、`F` FIXED、`C` CDROM、`W` REMOTE、`M` RAMDISK、`U` その他 |
| 3 | `N` | 既存方式で抽出 | `Y` / `N` |
| 4 | `Y` | 新方式で抽出 | `Y` / `N` |
| 5 | `S` | 新方式の結果の理由 | `S` 抽出、`U` USB でない、`V` ディスクのボリュームでない、`E` 番号取得の失敗、`K` ディスク種別でない、`M` ディスクなし、`P` ExpectNoRemoval、`I` 内蔵 USB、`X` その他 |
| 6 | `G` | ボリューム ID の形 | `U` `_??_USBSTOR#`、`S` `_??_SCSI#`、`T` `_??_` その他、`G` `{GUID}#オフセット`、`D` ドライブ自身、`X` 不明 |
| 7 | `U` | ディスクの列挙子 (`DEVPKEY_Device_EnumeratorName`) | `U` USBSTOR、`S` SCSI、`O` その他、`-` ディスクなし |
| 8 | `N` | 既存方式: ID が `USBSTOR#` を含む | `Y` / `N` / `-` |
| 9 | `N` | 既存方式: 親の ID が `USBSTOR\` を含む | `Y` / `N` / `-` |
| 10 | `S` | 取り外しポリシー | `N` NoRemoval、`O` Orderly、`S` Surprise、`-` 不明 |
| 11 | `Y` | USB デバイスの `CM_DEVCAP_REMOVABLE` | `Y` / `N` / `-` |
| 12 | `N` | USB デバイスが PC 本体のコンテナー内 | `Y` / `N` / `-` |
| 13 | `Y` | 最小改修案で抽出 ([legacy-minimal-flow.md](legacy-minimal-flow.md)) | `Y` / `N` |
| 14 | `U` | ディスクのバス種別 (`STORAGE_DEVICE_DESCRIPTOR.BusType`) | `U` Usb、`A` Sata / Ata、`N` Nvme、`S` Scsi / Sas、`D` Sd / Mmc、`R` RAID、`O` その他、`-` 取得できない |
| 15 | `S` | タスクトレイ方式の結果 ([safe-removal-flow.md](safe-removal-flow.md)) | `S` 抽出、`R` 安全な取り外しが要るノードなし、`U` USB でない、`V` ディスクのボリュームでない、`E` 番号取得の失敗、`K` ディスク種別でない、`M` ディスクなし、`X` その他 |
| 16 | `Y` | ディスク自身の `DEVPKEY_Device_SafeRemovalRequired` | `Y` / `N` / `-`。15 文字目が `S` で 16 文字目が `N` なら、TRUE だったのはディスクではなく祖先 (USB デバイス本体など) |
| 末尾 | `0F` | チェック値 (CRC-8) | 16 進 2 桁 |

### 形式のバージョン

ヘッダーの `UI3` が形式のバージョンです。

| 形式 | 追加した文字 |
|---|---|
| `UI1` | 1〜12 文字目 |
| `UI2` | 13、14 文字目 (最小改修案の結果とバス種別) |
| `UI3` | 15、16 文字目 (タスクトレイ方式の結果とディスク自身の `SafeRemovalRequired`) |

以前の形式で写したコードも、`--decode` でそのまま検証できます。行の長さで形式を見分けます。

## 含まれる情報

コードには、シリアル番号、PC 名、ボリューム GUID、インスタンス ID、ディスクのモデル名を含めていません。
機種の特定に VID:PID が必要なときだけ、`--vidpid` で各行に追加できます。

```
usbinfo -f code --vidpid
```

## 使う前に確認すること

- 検証環境に `usbinfo.exe` を持ち込んで実行してよいか。
- このコードのような検証結果を、手で写して環境の外へ持ち出してよいか。
- 既存コードの内容は写さず、「複数レターのとき最初の 1 つだけ登録するか」のような動作の確認結果だけを持ち帰ります。

QR コードや画面の撮影のように、コピーの制限を迂回する方法は、この手順では使いません。
