新方式は親子関係で USB を判定する

既存方式は GetDriveType と USBSTOR# の文字列で絞るため、USB 接続の SSD を取りこぼします。新方式はボリュームからディスク、USB デバイス本体へとたどるので、接続方式によらず USB ストレージを拾います。

既存方式

既存方式は「ドライブ種別」と「ID の文字列」の 2 つで絞る

漏れる理由

USB-SATA SSD のボリューム ID には USBSTOR# が入らない

ボリュームの ID の形は、ディスクがリムーバブルメディア扱いか固定ディスク扱いかで変わります。USBSTOR# が入るのは前者だけです。

新方式

新方式はディスク番号でボリュームをディスクに対応付け、ディスクの親から USB デバイス本体に届く

新方式は条件ごとに理由を記録し、-f letters の New: result 列に出します。どの条件で外れたかが 1 行で分かります。

移行

既存方式から新方式へは 5 つの変更で移る

呼び出し側の差し替えは次の順に進めます。

  1. 対象の PC で usbinfo -f letters を実行し、両方式の結果を並べる。
  2. Diff 列で LEGACY ONLY と NEW ONLY の行を確かめる。New: result 列が外れた理由を示す。
  3. 呼び出し側の SelectDrivesLegacy() を SelectDrivesNew() に置き換える。戻り値の型は同じ。
  4. namespace drivesel を移植するときは、setupapi.lib と cfgmgr32.lib をリンクする。
  5. ノート PC の内蔵カードリーダーを外したいときは SelectDrivesNew(true) にする。

新方式では GUID の照合も _wcsicmp にして、大文字小文字を区別しなくなりました。CM_Get_Device_ID は大文字の ID を返し、DEVPKEY_Device_InstanceId は元の大文字小文字のまま返すためです。

比較

新方式は USB 接続の固定ディスクを拾い、USB 以外は両方式とも外す
